::page{title="Exercise 2: Create a Dockerfile"}

In reading your story you see that the assumptions state that you must create a `Dockerfile` with the following attributes:

* Create a `Dockerfile` for repeatable builds
* Use a `Python:3.9-slim` image as the base
* It must install all of the Python requirements
* It should not run as `root`
* It should use the `gunicorn` wsgi server as an entry point

Let\'s take these in order.

## Your Task

1. Change to your project directory: `cd devops-capstone-project`.

1. Use the `git checkout -b add-docker` command to create a new branch called `add-docker` to work on in the development environment.

1. Run `nosetests` and make sure that all of the test cases are passing. Fix any failing tests before proceeding.

1. In the root of the repository, create a file named `Dockerfile`.

1. Edit the `Dockerfile` and start it `FROM` the `python:3.9-slim` image.

	<details>
	<summary>Click here for the answer.</summary>

	```
	FROM python:3.9-slim
	```

	</details>

1. Establish a `WORKDIR` of `/app`, `COPY` the `requirements.txt` file into the working directory in the image, and `RUN` the `pip` command to install the requirements using the `--no-cache-dir` option to keep the image small.

	<details>
	<summary>Click here for the answer.</summary>

	```
	# Create working folder and install dependencies
	WORKDIR /app
	COPY requirements.txt .
	RUN pip install --no-cache-dir -r requirements.txt
	```

	</details>

1. Copy the `service` package into the working directory of the same name in the image.

	<details>
	<summary>Click here for the answer.</summary>

	```
	# Copy the application contents
	COPY service/ ./service/
	```

	</details>

1. Create a non-root user called `theia`, change the ownership of the `/app` folder recursively to `theia`, and switch to the `theia` user.

	<details>
	<summary>Click here for the answer.</summary>

	```
	# Switch to a non-root user
	RUN useradd --uid 1000 theia && chown -R theia /app
	USER theia
	```

	</details>


1. Finally, `EXPOSE` port `8080` and create a `CMD` statement that runs: `gunicorn --bind=0.0.0.0:8080 --log-level=info service:app`

	<details>
	<summary>Click here for the answer.</summary>

	```
	# Run the service
	EXPOSE 8080
	CMD ["gunicorn", "--bind=0.0.0.0:8080", "--log-level=info", "service:app"]
	```

	</details>


## Results

You can check that your `Dockerfile` looks like the following:

<details>
    <summary>Click here to check your work.</summary>

```
FROM python:3.9-slim

# Create working folder and install dependencies
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Copy the application contents
COPY service/ ./service/

# Switch to a non-root user
RUN useradd --uid 1000 theia && chown -R theia /app
USER theia

# Run the service
EXPOSE 8080
CMD ["gunicorn", "--bind=0.0.0.0:8080", "--log-level=info", "service:app"]
```

</details>

::page{title="Exercise 7: Create Manifests"}

Here is a tip for getting started creating manifest yaml files. You can use the `kubectl` or `oc` CLI to create a deployment or service and capture the definition in a yaml file by adding the flags `--dry-run=client -o yaml`. This code doesn\'t actually create anything (`--dry-run=client`) but sends output to yaml (`-o yaml`). Then all you need to do is redirect that to a file.


1. Create a manifest definition for the account deployment using the `oc create deployment` command with the `--dry-run -o yaml` option and redirect it to a file called `deploy/deployment.yaml`. Specify the image that you pushed to the IBM Cloud registry and request three replicas.

	<details>
	<summary>Click here for the answer.</summary>

	```bash
	oc create deployment accounts \
	  --image=us.icr.io/$SN_ICR_NAMESPACE/accounts:1 \
	  --replicas=3 \
	  --dry-run=client -o yaml > deploy/deployment.yaml
	```

	</details>

1. Your microservice needs to know the details about the postgres database that you just deployed. In particular, it needs the following environment variables: `DATABASE_HOST`, `DATABASE_NAME`, `DATABASE_PASSWORD`, and `DATABASE_USER`. Use the `oc describe` command to see what keys are in the secret that you can use:

	<details>
	<summary>Click here for the answer.</summary>

	```bash
	oc describe secret postgresql
	```

	```text
	...
	Data
	====
	database-name:      8 bytes
	database-password:  16 bytes
	database-user:      7 bytes
	```

	</details>

1. Edit the `deploy/deployment.yaml` file and use the keys that you found in the secret along with a `DATABASE_HOST` of `postgresql` to add the required environment variables to the manifest.

	<details>
	<summary>Click here for a hint.</summary>
	You can create an environment variable from a secret key like this:

	```yaml
       env:
        - name: DATABASE_NAME
            valueFrom:
            secretKeyRef:
                name: postgresql
                key: database-name
	```

	</details>

	<details>
	<summary>Click here for the answer.</summary>

	```yaml
            env:
              - name: DATABASE_HOST
                value: postgresql
              - name: DATABASE_NAME
                valueFrom:
                  secretKeyRef:
                    name: postgresql
                    key: database-name
              - name: DATABASE_PASSWORD
                valueFrom:
                  secretKeyRef:
                    name: postgresql
                    key: database-password
              - name: DATABASE_USER
                valueFrom:
                  secretKeyRef:
                    name: postgresql
                    key: database-user
	```

	</details>
